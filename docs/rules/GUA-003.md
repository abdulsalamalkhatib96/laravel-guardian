# GUA-003 — Sensitive attribute exposed by API serialization

**Default severity:** HIGH. Secret credentials/tokens escalate to CRITICAL.

## Sensitive sources

Guardian combines:

- configured sensitive model fields;
- model `$hidden` fields;
- known secret field names.

## Serialization sinks

V1 understands:

- `JsonResource::toArray()` payloads;
- `response()->json(...)`;
- `Response::json(...)`;
- `new JsonResponse(...)`;
- direct model visibility overrides such as `makeVisible()` when returned.

## Unsafe

```php
final class PlayerResource extends JsonResource
{
    public function toArray($request): array
    {
        return ['phone' => $this->phone];
    }
}
```

## Local taint propagation

```php
$phone = $player->phone;

return response()->json([
    'contact' => $phone,
]);
```

The output key does not need to match the original sensitive field name.

## Safe sanitizer

```php
return [
    'phone' => Str::mask($this->phone, '*', 3),
];
```

Only explicitly configured sanitizers are trusted. Guardian does not assume arbitrary hashing, substring operations, or custom helper names are safe.

## Conditional authorization

A field wrapped in helpers such as `when()` is not automatically proven safe. Guardian lowers confidence because it cannot generally prove the authorization predicate is correct for every route and caller.

Use a documented narrow suppression when intentional exposure is protected by a reviewed authorization invariant.

## Intentional exposure

Use `#[GuardianAllowsSensitive(fields: [...], reason: '...')]` on the specific resource method or class when a sensitive field is intentionally returned. The allowance is field-specific and requires a reason; it does not disable the whole rule.
