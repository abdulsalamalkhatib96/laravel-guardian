# GUA-001 — External side effect inside database transaction

**Default severity:** CRITICAL for HTTP/process effects, HIGH for queue/mail/notification/filesystem classes of effect.

## Failure mode

A database transaction can roll back; an external system often cannot. Executing an irreversible effect before commit creates a split-brain state between the database and the remote side.

## Unsafe

```php
DB::transaction(function () use ($withdrawal) {
    $withdrawal->update(['status' => 'processing']);
    Http::post($providerUrl, ['id' => $withdrawal->id]);
});
```

## Safe patterns

### Perform after commit

```php
DB::transaction(function () use ($withdrawal) {
    $withdrawal->update(['status' => 'processing']);
    SendProviderRequest::dispatch($withdrawal->id)->afterCommit();
});
```

### Transactional outbox

Write both domain state and an outbox record in the same transaction; deliver the outbox asynchronously after commit.

## Detection

Guardian recognizes supported Laravel transaction primitives, direct effects, configured SDK methods, and follows resolvable application calls while transaction state is active.

## Intentional exceptions

Use a narrow suppression only when the remote operation is itself safely compensatable/idempotent and the system design explicitly tolerates the ordering. Document that reasoning in the suppression reason.

## Limitations

Runtime-selected service implementations and dynamic method names may prevent call resolution. Register custom external SDK methods through `rules.GUA-001.custom_effects`.
